# Devlog – FastAPI Bookstore

## 2025-08-25

**What I did:**
- Updated a `Dockerfile` so it creates a non-root `appuser`, and runs FastAPI under it.

- Removed `user: "1000:1000"` from `docker-compose.yml` since it overrides Dockerfile’s `USER` choice.

- Added meaningful logging to all FastAPI endpoints in `app/api/book.py`.

- Added logging to all CRUD operations in `app/crud/book.py`

- Used different logging levels: `info` for successful operations, `debug` for detailed DB info, `warning` for recoverable issues, and `exception` for errors.


<br>
<br>

**What I learned:**
- You don’t need a password for container users (`appuser` is only for runtime security).

- Using `--reload` in `Dockerfile` is fine for dev but not recommended for production.

- If there are some changes in the `Dockerfile`, you need to rebuild the image.

- Proper logging is essential for tracking API usage and database operations.

- Using multiple log levels allows easier filtering during development vs production.

- Models and schemas usually don’t need logging unless doing heavy internal processing.
