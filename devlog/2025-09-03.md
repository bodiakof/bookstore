# Devlog – FastAPI Bookstore

**What I did:**
- Added `Contributor` model to represent authors, translators, illustrators, etc.

- Added `BookContributor` association model to handle many-to-many relationship between books and contributors, with an extra `role` column.

- Created `ContributorRole` enum to define contributor roles (AUTHOR, TRANSLATOR, ILLUSTRATOR).

- Updated `Book` model:

    - Added `contributors_assoc` (link to `BookContributor` rows).

- Updated `base.py` to import models via `from app.models import *` instead of listing each one individually.

- Ensured all models (including association tables) are registered with `Base.metadata` for migrations and schema creation.
<br>
<br>

**What I learned:**
- The difference between `relationship(..., back_populates=...)` and `relationship(..., secondary=...)`.

   - `back_populates` ties two relationship attributes so navigation works in both directions.

   - `secondary` is used for many-to-many when you want a shortcut to jump directly from one side to the other.

- Why the `role` column must live in the `BookContributor` association model (since it’s contextual, not intrinsic to the contributor).

- How using both `contributors_assoc` and `contributors` provides flexibility:

   - `contributors_assoc` → full access to `role` and metadata.

   - `contributors` → quick access to `contributors` without worrying about roles.

- SQLAlchemy only creates tables for models that are registered with `Base.metadata`.

- If a model isn’t imported before running `create_all` or Alembic autogenerate, its table won’t appear in the database.

- Using a central `models/__init__.py` avoids the risk of forgetting to register new models in `base.py`.
