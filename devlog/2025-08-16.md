# Devlog – FastAPI Bookstore

## 2025-08-16

**What I did:**
- Added `isbn` column to books table with unique constraint.

- Created utility `generate_fake_isbn()` for generating fake ISBNs for testing.

- Updated `create_books` to assign fake ISBNs if none provided and handle duplicate ISBNs.

- Updated `update_book` to catch duplicate ISBNs and return a 400 instead of 500.

- Refactored `BookCreate` and `BookUpdate` schemas to allow optional ISBN.

<br>
<br>

**What I learned:**
- Alembic migrations need careful handling when adding a unique column to a table with existing data.

- Catching `IntegrityError` is essential when enforcing unique constraints to prevent 500 errors.

- Pydantic `BaseModel` schemas make partial updates much cleaner with optional fields.
<br>
<br>

**Questions:**
- Should we pre-check ISBN uniqueness before commit to avoid catching exceptions at all?
<br>
<br>

**Bugs encountered:**
- 500 Internal Server Error when updating a book with a duplicate ISBN before adding exception handling.

- Duplicate ISBNs during migration caused Alembic unique index creation to fail.
